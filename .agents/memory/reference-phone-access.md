# 在手機上玩

## 為什麼一定要 HTTPS
- 旋轉手機轉向用的是瀏覽器的 `devicemotion`，瀏覽器只在安全來源（HTTPS 或 localhost）提供。用 `http://<電腦IP>:8765` 開，遊戲能跑但偵測不到傾斜，只能在畫面上左右拖曳轉向。
- claude.ai 的 artifact 頁面會擋動作感應器，所以這個遊戲不能用 artifact 發布。

## 目前做法：本機自簽憑證
- `start.bat` → `node server.js` 會同時開 HTTP 8765（電腦）與 HTTPS 8766（手機）。
- 憑證由 `server.js` 用 Git for Windows 內附的 openssl 產生，放在 `.cert/`（已列入 `.gitignore`）；電腦的 IP 變了會自動重新產生。
- 手機與電腦在同一個網路，手機開啟動視窗顯示的 `https://<電腦IP>:8766/`，第一次會有「連線不是私人連線」警告，按「進階」→「繼續前往」。
- Windows 第一次會問防火牆，要按允許。
- **已在使用者手機上驗證（2026-11-11）**：同一個 Wi-Fi 下連得到，接受自簽憑證警告後傾斜感應可用（可以旋轉手機轉向）。所以目前不需要對外發布。
- 全螢幕：手機退出全螢幕後遊戲會自動暫停，按暫停選單的「繼續」或「全螢幕」會再進全螢幕（瀏覽器規定要由使用者點擊觸發，不能自動進）。

## 手機連不到電腦時
- alms 專案的經驗（2026-10-11）：使用者家裡的 Wi-Fi 下手機與電腦互相連不到，改用「手機開熱點、電腦連熱點」就可以。這裡先用同樣做法，熱點重開後 IP 可能會變，以啟動視窗顯示的網址為準。

## 對外發布（備案，尚未做）
- 需要固定網址或不想開電腦時，可放到 GitHub Pages 這類有 HTTPS 的靜態空間。發布會讓遊戲變成公開網址，要先問使用者。
- 注意：`node_modules` 在 `.gitignore` 裡，而 `js/world.js` 是從 `../node_modules/three/build/three.module.js` 匯入。發布前要把這個檔案複製到會被提交的位置（例如 `vendor/`）並改匯入路徑，否則線上會載入失敗。
